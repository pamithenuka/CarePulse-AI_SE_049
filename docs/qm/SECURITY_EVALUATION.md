# Security evaluation protocol

Declared 3 October 2026 before the new security probes. Scope: CarePulse's HTTP authentication, authorization, ownership and validation controls using xUnit + WebApplicationFactory against disposable local PostgreSQL. Existing fixtures substitute AI; no external scan target or shared Neon traffic.

## Method and acceptance

Use executable HTTP probes with assertions for expected status and persisted state. This is tool-based application security testing with xUnit/ASP.NET, a justified targeted alternative to a generic scanner for these role-specific workflows. It is not a ZAP scan, penetration-test certification, dependency audit or production TLS/header assessment.

| Group | Input/action | Required result |
| --- | --- | --- |
| Anonymous access | Read triage queue, patient registry, dispatch list, private-file path without token | 401, no sensitive content |
| JWT signature | Alter an otherwise valid token signature | 401 |
| Role restriction | Admin tries doctor-only triage approval | 403; case remains unapproved |
| Object ownership | Patient B uploads to patient A's vault | 403; no document row |
| Unsafe upload | HTML extension, forged PNG header, or empty PDF | 400; no document row |
| Input validation | Triage with invalid latitude | 400; no triage created |
| Existing controls | Expired JWT, other patient's case read, wrong nurse telemetry, public role escalation, unapproved dispatch | Existing HTTP assertions pass |

Only expected refusals count as passes; a 500 or unreachable server is not an acceptable security outcome. Use valid synthetic tokens generated by the test host except in the explicit invalid-token case. Refusal before persistence must be checked through a fresh database context where applicable.

## Reproduce

Set `CAREPULSE_TEST_CONNECTION` to isolated local PostgreSQL (current local test instance: loopback 55441). From repository root:

```sh
dotnet test tests/CarePulse.Api.Tests --configuration Release --filter 'FullyQualifiedName~IntegratedWorkflowTests' --logger trx --results-directory NEW_SECURITY_RESULTS_DIRECTORY
```

Fixture databases are disposable and removed by the suite. Do not use shared Neon. Results describe only the implemented probes and the inspected version; scanner/production deployment controls remain unassessed.

## Results — 3 October 2026

**17 tests passed, zero failed/skipped:** 11 new parameterized HTTP security cases and 6 existing integrated/security workflow cases. The expected 401/403/400 refusals and database no-write assertions passed. Existing cases additionally exercised doctor approval, wrong-nurse access, expired credentials, cross-patient reads, privilege escalation and adversarial workflow handling. Raw case names/outcomes are in `evidence/security-20261003/results-summary.json`; TRX and tool log are alongside it.

No new production vulnerability was exposed by this bounded set. Passing these probes does not establish that the application is free of vulnerabilities. No successful malicious upload was created; forged PNG checks validate the implemented signature gate, not full image decoding or malware detection. Anonymous file denial tests the route gate; full private-file download ownership still warrants separate coverage.

## Finding triage and limitations

The compiler emitted EF1002 in MigrationTests.cs for interpolated DDL identifiers. Inspection found a fixed, internal list of three table names (`AppointmentSlots`, `ClinicRosters`, `ConsultationRecords`) in a test fixture. No user input enters those identifiers. It is not a demonstrated SQL injection vulnerability; the warning is preserved, not suppressed or presented as a penetration-test finding.

No generic scanner, dependency vulnerability audit, deployed TLS/headers, login brute-force/rate-limit test or complete upload parser audit was executed. These are unassessed areas, not passes. Shared doctor visibility/specialty routing remains the documented product limitation. Existing production defect QM-AI-001 belongs to AI evaluation; this run did not manufacture a security bug for reporting.
